Introduction
The agile product backlog in Scrum is a prioritized list of product capabilities and work items that are refined as the team learns more about the product. For Smart Scheduling, the backlog translates the approved single-store F&B scope into concise role-based needs for Admin, Manager, and Staff. It provides the basis for Sprint planning, refinement, implementation, testing, and review while remaining aligned with the project Proposal and User Story Document.

Purpose
Provide a prioritized list of the functions required to deliver the Smart Scheduling product within the approved Capstone scope.
Give the Scrum team a common implementation reference that connects user needs, business value, and feature priority.

Scope
Lists the official user roles: Admin, Manager, and Staff.
Includes employee/skill management, availability, shifts, manual and automatic scheduling, leave/swap/open-shift workflows, GPS attendance, timesheets, dashboard/reporting, notifications, and optional AI support.
Keeps the implemented business scope to one F&B store; multi-store and multi-tenant functions are deferred.
Prioritizes product functions from 1 to 5 so dependencies and core workflows can be planned before optional enhancements.
Uses Laravel/Microsoft SQL Server as the core system while Scheduling Service and AI Service remain independent enhancement services.
