	    1. Introduction
In software development, a User Story describes a capability from the perspective of a system user in business language. It captures who needs a capability, what they need, and why it provides value. In Smart Scheduling, user stories connect F&B workforce needs with implementable functions and testable acceptance criteria.
The stories in this document support requirement clarification, Product Backlog planning, development, testing and review. Acceptance criteria define expected behavior and do not imply that a feature has already been completed.
		    1.1 Overview document
	This document provides a user-story and goal-oriented view of Smart Scheduling and supports the project by:
	Defining what Admin, Manager and Staff need from the system within the official single-store scope.
	Providing acceptance criteria that can be converted into test cases and Definition-of-Done checks.
	Maintaining traceability between operational needs, scheduling behavior, attendance/timesheet workflows and implementation planning.
	Providing a common reference for the team, mentor, reviewers and stakeholders during Scrum refinement and review.
		    1.2 Project background
		    1.2.1 Business value
	Small and medium F&B stores often rely on part-time staff whose availability changes frequently. Managers must reconcile availability, skills, staffing requirements, leave, working-hour/rest constraints and last-minute changes while also verifying actual attendance. Spreadsheet and chat-based coordination increases repeated manual work, makes conflicts easier to miss and makes actual working-hour reporting harder to control. Smart Scheduling aims to improve staffing visibility and provide one consistent workflow from availability to published schedules, attendance, timesheets and reports.
    1.2.2 Solution
	Smart Scheduling is a Web and Mobile workforce-management system for one F&B store. React Web supports Admin and Manager workflows, while Staff use the Mobile App for availability, published schedules, GPS attendance, leave, shift swap/open shift, timesheets and notifications. Laravel and Microsoft SQL Server form the always-available core; Redis supports queue/cache. Python/FastAPI with Google OR-Tools CP-SAT generates constraint-aware Draft Schedules, while an optional AI service explains verified data. Manager confirmation remains required for official schedule and workforce decisions.
